# Pankeki 로고 원본 시각 검토

검토 시각: 2026-10-19 21:54 KST

현재 세 후보 중 A를 우선 권장한다. A는 흰색과 짙은 배경에서 팬케이크 층과 전체 형태가 가장 안정적으로 보인다. B는 흰색 전용 적용 후보이며, 교체된 C는 형태는 정돈되었지만 원본 여백 때문에 작은 헤더 아이콘에서 지나치게 작게 보인다. 이는 디자인 판단이며 사용자 선택이나 최종 확정으로 기록하지 않는다. 디자인 담당이 알려준 8190의 A 적용도 임시 미리보기이며 사용자 최종 선택이 아니다.

## 검증 범위와 자료

- 원본 A: `D:\Pankeki\web\assets\pankeki-logo-option-a.png`
- 원본 B: `D:\Pankeki\web\assets\pankeki-logo-option-b.png`
- 최종 비교용 원본 C: `D:\Pankeki\web\assets\pankeki-logo-option-c.png`
- 제외된 이전 C 초안: `D:\Pankeki\web\assets\pankeki-logo-option-c-draft.png`
- 비교 HTML: `D:\Pankeki\work\logo-review\comparison.html`
- 실제 브라우저 캡처: `D:\Pankeki\work\logo-review\comparison-1440.png`
- 원본 SHA-256 및 투명도 측정: `D:\Pankeki\work\logo-review\capture.json`
- 재현 스크립트: `D:\Pankeki\work\logo-review\render.cjs`

프로젝트의 기존 설치된 Playwright와 Chrome headless 구성을 사용했다. 새 패키지를 설치하지 않았다. 독립 브라우저 페이지에 자체 작성한 HTML을 넣고 PNG 원본을 data URI로 내장했다. 배경은 흰색 `#ffffff`와 짙은 `#252a23`, 표시 크기는 32·48·256 CSS px이며 DPR은 1이다. 원본을 자르거나 색상·알파·선명도를 수정하지 않았다. 원본과 실제 브라우저 캡처를 view_image로 확인했다.

이 비교표는 로고 검토 화면이며 실제 Pankeki 앱 화면이 아니다. 8190 최종 헤더에 통합한 상태는 별도 검증해야 한다.

## 후보별 판단

| 후보 | 256px | 32·48px | 짙은 배경 | 판단 |
|---|---|---|---|---|
| A | 따뜻한 노란 팬케이크와 진한 외곽선이 명확하다. 네 겹의 형태가 안정적이다. | 32px에서도 팬케이크 묶음은 식별되며, 48px에서 층 구분이 더 편하다. 작은 버터 윤곽은 32px에서 점에 가까워진다. | 노란 면이 남아 형태와 층이 유지된다. | 현재 후보 중 우선 권장. 친숙한 음식 아이콘이며 특별한 창작 도구 의미까지 표현된 것은 아니다. |
| B | 세 개의 짙은 갈색 원반과 노란 버터로 가장 단순하다. 흰 배경에서는 경계가 깨끗하다. | 흰 배경의 32px에서도 층 사이의 빈 공간이 보인다. | 갈색 면과 배경의 밝기 차이가 작아서 아래 두 층이 약해지고 작은 크기에서 하나의 어두운 덩어리처럼 보인다. | 흰 화면에 한정하면 가능하지만 두 배경 공용 로고로는 A보다 약하다. |
| C 교체본 | 얇은 팬케이크 세 장을 측면에서 보는 형태로 초안보다 정돈됐다. 다른 두 후보보다 그림이 훨씬 작게 들어 있다. | 32px 박스에서 실제 그림 높이가 약 8.4px, 48px에서도 약 12.6px에 불과해 얇은 줄 묶음처럼 보인다. | 금색 면은 구별되지만 층 사이의 흰 띠가 그대로 보인다. 이 띠는 배경이 비치는 투명 틈이 아니다. | 현재 원본 그대로 작은 헤더에 적용하기에는 A보다 약하다. 다른 후보와 동일 크기 박스 비교에서는 여백의 영향이 크다. |

## 실제 투명도와 원본 여백

세 PNG 모두 1254×1254이고, alpha 최솟값 0·최댓값 255를 가진다. 흰 바탕이 이미지에 붙은 가짜 투명 PNG는 아니다. 대부분의 그림 픽셀은 alpha 224–254에 있으며, 전체에 반투명 픽셀이 많다는 숫자만으로 품질 실패를 판단해서는 안 된다.

| 후보 | alpha 1–31 픽셀 수 | alpha ≥128의 실제 그림 크기 | 32px 이미지 박스 안의 실제 그림 크기(근사) |
|---|---:|---:|---:|
| A | 4,623 | 894×666 | 22.8×17.0px |
| B | 13,668 | 1039×682 | 26.5×17.4px |
| C 교체본 | 5,137 | 732×328 | 18.7×8.4px |

교체된 C에도 실루엣 밖의 낮은 알파 픽셀이 있으나 이번 목표 크기 렌더에서 뚜렷한 얼룩은 보이지 않았다. C 교체본의 주된 문제는 작은 크기의 식별성과 큰 여백이다.

이전 C 초안은 원본 가장자리의 들쭉날쭉한 알파 잔여와 형태 문제로 디자인 담당이 제외했다. 초안 검토 당시 alpha 1–31 픽셀이 19,538개였고 그림 밖으로 넓게 분포했다. 다만 32·48·256px 브라우저 렌더에서는 원본 뷰어에서 보인 노란/붉은 흔적이 뚜렷하게 나타나지는 않았다. 초안 비교 자료는 `comparison-with-c-draft.html`, `comparison-with-c-draft-1440.png`, `capture-with-c-draft.json`으로 `work/logo-review/`에 보존했다. 최종 `comparison.html`과 `comparison-1440.png`에는 교체된 C만 사용한다.

세 후보 모두 원본 여백 때문에 CSS 이미지 박스보다 실제 로고가 작다. 특히 C의 실제 그림 높이는 원본 높이의 약 26%다. A 원본을 그대로 사용할 경우 헤더에서 가능하면 48px 이미지 박스를 확보하고, 최종 헤더의 실제 32px/48px 표시를 다시 확인하는 편이 좋다. 이번 작업에서는 여백이나 알파를 수정하지 않았다.

## 남은 검증

- 사용자 최종 선택을 반영한다. A는 권고 및 임시 미리보기이지 최종 확정이 아니다.
- 선택한 원본의 최종 앱 헤더·모바일 화면 배치와 실제 화면 대비를 확인한다.
- 이 검토는 DPR 1 Chrome 기준이다. 다른 브라우저·DPR 2 이상의 화면은 검증하지 않았다.

변경 파일은 `work/logo-review/`의 검토 자료와 이 문서뿐이다. `web/` 소스와 로고 원본에는 쓰지 않았다.
