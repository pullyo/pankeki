# 제품 기획 및 리서치 1차 인계

2026년 10월 20일 KST · 1차 결과 작성 완료 · 총괄 검토 대기

**추천은 후보별 수동 요구 확인과 미충족 한 항목의 부분 수정 연결이다.** 기존 채팅 중심 화면·큰 캔버스·후보 비교·부분 수정·프로젝트 저장과 사용자 모델 방향을 유지한다. 생산 코드·설치·다운로드·GPU 생성·원격 게시·다른 채팅 메시지는 수행하지 않았다. 복구 기준 백업은 수정하지 않았다.

## 완료 사항

지정한 세 문서를 `TEAM-OPERATIONS.ko.md` → `shutdown-checkpoint.md` → `TEAM-CONTEXT.ko.md` 순서로 읽었다. 최신 체크포인트와 재개 기능 담당 인계를 우선하여 SDK 미구현·SD Turbo 기본값이라는 과거 설명을 현재 상태로 채택하지 않았다.

- 제품 목표·보존할 기능·품질 실패를 정리했다. 저장 9개 PNG와 가방 편집 1개를 직접 열었고, 전체 요구 통과 0/9, C군 단일 전신 3/3과 장갑·벨트 소품 실패를 확인했다. 실행 성공과 이미지 품질을 분리했다.
- 공식 대회 공고와 현재 동적 요건 리소스를 확인했다. 제출 요건·KST 마감·읽을 수 없었던 폼 문항 범위를 기록했다. SDK 서비스 사양은 현재 공식 문서를 확인했다. 새 모델 비교나 모델 사양 재조사는 하지 않았다.
- 새 모델 없이 가능한 3개 과제를 효과·코드 기반·비용/의존성·검증 기준으로 비교했다. 1순위의 사용자 흐름·저장 계약 제안·회귀 기준을 구체화했다.
- 기능팀의 가방 denoise 비교 계획을 읽었으며 실험 조건을 바꾸지 않았다. 제품 검수 기록과 실제 재질 품질 실험을 별도 작업으로 정의했다.

최초 셸 네트워크 조회는 sandbox 소켓 접근 오류였으며 승인된 네트워크 읽기로 재실행해 현재 원문을 확보했다. `web.run`은 공식 JS 자산 직접 읽기를 지원하지 않아 현재 HTTP 원문 조회를 사용했다. Typeform은 본문 질문이 읽기 결과에 노출되지 않아 실제 필수 문항 확인을 남겼다.

## 한계와 다음 작업

1순위는 사용자가 실패를 확인하고 다음 수정을 잇게 하는 제품 개선이다. 이미지 의미·재질 품질이 해결됐다는 결론이 아니다. 소요 인일은 기획 추정이며 성능·사용 시간 절감·수상 가능성을 검증하지 않았다. 실제 GPU나 재개 서비스 상태는 이번 담당의 검증 범위가 아니다.

최소 범위에도 판정 저장이 필요하다. 현재 strict parser가 임의 필드를 거부하므로 version 2 및 v1 가져오기 지원 방향을 제안했다. 이 형식과 DOM 계약은 총괄 검토 후 기능·디자인 담당이 확정해야 한다. 확정 전 구현을 시작하지 않는다.

기획팀 확대 지시 이후 기술 리서치와 사용자·경쟁제품 리서치는 다른 담당이 맡는다. 첫 인계 시 그 결과는 아직 읽지 않았다. 수동 판정의 사용자 효과, 기존 제품과의 의미 있는 차이, 현재 PC에서의 복구 가능성은 검토가 남은 가정으로 제품 문서에 분리했다. 비용은 담당별 재산정 대상이다. 모델·워크플로·경쟁제품 심층 조사를 중복하지 않았다.

총괄은 제품 1순위 채택 여부와 저장 형식 조정 범위를 검토하면 된다. 기능팀 단일 변수 실험 실행은 환경팀 인계와 함께 별도로 결정한다. 출시팀은 공식 요건 문서를 이용해 최신 공개본·데모·폼 문항을 확인한다. 이번 담당은 첫 기획 결과를 남기고 총괄 검토를 기다린다.

## Live2D 아이디어 추가 인계

추가 사용자 요청에 따라 `docs/product/live2d-ideas.md`를 작성했다. 공식 Editor 매뉴얼에서 대상별 파라미터 표시·기본 키폼 잠금·변경/비변경 대상 확인·파라미터/디포머 개념을 확인하고, 제품 적용 해석 및 아직 필요한 검증과 구분했다. Cubism 5.3.04 공개일은 공식 릴리스 목록으로 확인했으며 설치 Editor를 직접 조작한 결과로 표시하지 않았다.

우선은 **수정 목표와 보존 범위 확인**, 후속은 **이름 붙인 수정 영역**, **변경 항목별 기준과 후보 비교**다. 앞선 요구 확인 과제와 묶어 중복 개발을 피한다. 현재 실패·코드 재사용·저장 신뢰성·사용자 부담의 평가 기준과 최소 검증을 남겼다. 첫 작성 시 기술팀 `live2d-transfer.md`와 사용자팀 `live2d-workflows.md`는 검색에서 확인되지 않아 결과별 검토 질문을 분리했다. 런타임·자동 리깅·새 모델·생산 코드는 도입하지 않았다.

제품·대회 첫 결과는 보존했다. 파일 소유권의 최신 변경에 따라 화면 상태·프로젝트 저장 계약의 구현 검토 대상은 프론트엔드 담당이며, 엔진 품질 실험은 기능 담당이다. Live2D 출처 목록은 planning/evidence.json, 문서 검증은 planning/validation.json에 함께 기록한다. 총괄 검토 후 두 리서치 자료를 반영하는 것이 다음 작업이다.
