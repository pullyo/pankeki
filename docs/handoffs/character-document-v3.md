## Loading and namespaces

UMD/CommonJS. Browser dependency order: profiles.js → character-document.js → character-document-v3.js; character-renderer.js and character-document-v3.js must precede character-renderer-v3.js. New browser globals are `PankekiDocumentV3` and `PankekiRendererV3`. No build/template integration was made in Task 6.

Document namespace:

| API | Contract |
|---|---|
| `upgradeV2(raw, {decodeAsset} = {})` | Promise of a frozen, validated V3. Only explicit v2 input accepted. It validates/copies v2, copies its three definitions/current values and every legacy binding, assigns deterministic `legacy-N` binding IDs. Original object/asset strings are unchanged. |
| `parseDocumentV3(raw, {decodeAsset} = {})` | Promise of a frozen V3 from JSON string/plain data. Requires explicit v3 wrapper and v2 base. Strict unknown-field, dense-array, finite-number, duplicate-ID and reference checks. Recomputes canonical rigHash. Never routes v1/v2 input into v3 automatically. |
| `serializeDocumentV3(doc, {decodeAsset} = {})` | Promise of JSON string after revalidation/hash recomputation. Parsed documents retain the supplied decoder privately; it is inherited unless explicitly overridden. No history or decoder is serialized. |
| `createEditorV3(doc, {decodeAsset, historyLimit=50, maxHistoryBytes=33554432} = {})` | Synchronous editor creation; requires this namespace's validated immutable document. Returns `snapshot`, `dispatchBatch`, `undo`, `redo`. Retains/inherits decoder for commit validation. |
| `assertDocumentV3(doc)` | Synchronous identity/validation guard; returns doc or throws. Cloning a parsed doc requires parsing again. |
| `resolveValuesV3(doc, overrides={})` | Synchronous new plain value object merging complete committed values with validated partial numeric overrides; throws for unknown IDs/nonfinite/out-of-range values. |
| `compatibilityV3(doc)` | Synchronous frozen `{stalePresetIds, staleMotionIds}` arrays from hash mismatches. Staleness is derived, not an extra serialized field. |
| `presetValuesV3(doc, presetId)` | Synchronous copy of a compatible preset's complete values. Throws for missing/stale preset. Does not commit or change preview. |

Renderer namespace:

| API | Contract |
|---|---|
| `evaluatePoseV3(doc, overrides?)` | Synchronous legacy-compatible `{backgroundAssetId, draws, blockedParts}` pose. Requires branded frozen V3; resolves partial overrides, evaluates extension axes once, checks combined geometry, then reuses legacy affine/order/visibility/blocking evaluation. Invalid combined geometry throws before producing a new pose. |
| `sampleMotionV3(doc, motionId, seconds, {loop=false}={})` | Synchronous partial value object from linear motion curves. Requires motion from doc by ID and matching hash; throws for stale/missing motion or nonfinite time (negative time also rejected when looping). Nonloop time clamps to 0..2; loop wraps modulo 2. |
| `drawPoseV3(canvas, pose, decodedAssets)` | Same signature/return as legacy `drawPose`; delegates its canvas validation/staging. No masks or warp rendering added. Caller evaluates successfully before drawing and preserves the prior frame on thrown evaluation errors. |

All async parser/editor errors reject their Promise; synchronous guard/evaluator/helper errors throw `Error`. No new stable error-code enum is promised.

## Schema and preservation

`{format:'pankeki-authoring',version:3,baseDocument,parameterDefinitions,values,bindings,clipRelations,deformers,partDeformerIds,rigHash,presets,motions}`.

`baseDocument` is the legacy parser's validated v2 copy. It keeps original asset data strings/bytes, topology, parent hierarchy, parameters, presets and motions. Legacy parser normalization (for example stale rig status) still applies on raw imports. Upgrade does not split eyes, add artwork, rewrite the original project/DB, or promote legacy presets/motions to new active v3 entries: the new v3 arrays start empty and originals remain in baseDocument. A v1 caller must explicitly use the legacy conversion to v2 before requesting upgrade.

Definitions: up to 32 `{id,label,min,max,default,unit}`, finite arbitrary min < max and default in range. Labels up to 80 chars, units up to 40; IDs use existing ASCII identifier convention. Complete `values` has exactly defined IDs. Draft strings such as `0.` live in future UI state, never this schema. Numeric input is rejected rather than clamped; v2 behavior stays unchanged. Signed/large finite parameter ranges are supported, including spans whose direct subtraction overflows.

Axis binding: `{id,partId,mode:'axis',parameterIds:[id],keys:[{at,deltas}]}`; maximum 512 bindings and 32 keys per binding, one binding per part/parameter pair. Keys strictly increase, include range endpoints and the declared default, and default deltas must all be zero. Vertex counts and per-key triangle orientation must remain valid. Sum-of-axes geometry is checked again at evaluation. All existing limits remain: 16 parts, 1024px canvas sides, 256 vertices, 512 triangles, UV/asset validation and JSON budget. Individual valid keys do not establish safety for every combination.

Replacement is **per part**, not per axis: if any v3 binding exists for a part, all its legacy bindings are ignored; extension deltas are applied once to its base vertices. Other parts retain legacy bindings. Upgrade explicitly copies all legacy bindings, so defaults and nondefault values numerically match legacy output.

Deleting the last v3 binding for a part intentionally restores that part's legacy evaluation. UI must not label this operation “fully disconnect.” To suppress all legacy deformation within the current schema, keep one valid axis binding for that part with zero deltas at all keys. This neutral replacement suppresses every legacy axis for that part. Changing/removing a definition must supply compatible complete values and rewritten/deleted dependent bindings in the same batch. Unreplaced legacy bindings require their original parameter definition/range/default.

Task 6 supports only `clipRelations:[]`, `deformers:[]`, `partDeformerIds:{}` and axis bindings. Nonempty future clip/deformer fields and grid/warp modes fail explicitly, including via editor commands. Tasks 7/8 must extend validation, hashing and evaluation together; they must not bypass validation or silently drop unsupported data.

## Hash and saved-item guards

SHA-256 over deterministic sorted-key JSON includes base canvas, source/background/candidate asset references, full asset data, parts (including parents/transforms), rigs (including topology/UV/base bindings/status), base definitions excluding values, v3 definitions/bindings and all extension graph fields. It excludes transient v3 values, base parameter values, current selection, presets and motions. Label/order changes inside included definition/shape records can conservatively invalidate saved items.

Parser recomputes the hash rather than trusting the incoming 64hex value. Stale preset/motion original hashes and data remain saved, even if their historical parameter IDs/ranges no longer exist. Their structure/finite numbers/time ordering remain validated. Current-hash records must also match current definitions. Never execute historical records by stripping a hash or silently clamping values. `savePreset`/`saveMotion` rejects a hash that differs from the final batch's computed hash.

V3 presets: `{id,label,rigHash,values}`; maximum 64. V3 motions: `{id,label,duration:2,fps:24,rigHash,curves:[{parameterId,keys:[{t,value}]}]}`; maximum 32 motions, 32 unique curves per motion, 32 keys per curve; keys cover 0..2 and loop endpoints agree. Empty curves are permitted. Task9 UI/export must call `presetValuesV3` or `sampleMotionV3` against the current document immediately before use; export must reject stale motions. These helpers do not execute rendering or exports themselves. After a shape edit, obtain the new snapshot/hash before explicitly saving a newly authored item; do not rewrite an old item's hash automatically.

## Atomic editor and decoding

`dispatchBatch([{type,value}, ...])` always returns a Promise of snapshot. Commands are captured/validated as plain JSON synchronously at call time (including input-copy errors returned as rejected Promises). Valid batches enter a FIFO queue. The queue remains usable after failures; `undo()` and `redo()` use the same queue and return Promises. Await completion before updating committed UI/export state.

Commands: `setParameterDefinitions`, `setValues`, `setBindings`, `setClipRelations` replace the entire corresponding field. `setDeformers.value={deformers,partDeformerIds}` replaces both. `savePreset`/`saveMotion.value` is one full record, inserted/replaced by ID. Unknown command fields/types fail. A maximum of 130 commands is applied to a private draft and revalidated only at the end, so dependent definition/value/binding changes form one transaction.

Snapshot is frozen `{document,revision,canUndo,canRedo,undoCount,redoCount,historyBytes}`. Only a changed, fully valid final document increments revision and adds one undo entry; a canonical no-op preserves revision and redo. Failure preserves current document identity, revision, undo and redo. Concurrent callers run in enqueue order using the latest committed document: there is no `expectedRevision` field. UI requiring optimistic concurrency must compare snapshots before dispatch or serialize its own edit session.

Undo/redo restores previously validated immutable snapshots without re-decoding or hashing, increments revision on an actual move and remains safe if the decoder later fails. History uses a shared immutable baseDocument asset graph; extension snapshots are counted in the bounded history-byte estimate. `historyLimit` accepts 0..50, byte budget 0..33554432. No-op undo/redo leaves revision unchanged. The byte counter is serialized extension storage accounting, not a total JavaScript heap measurement.

`decodeAsset(asset)` follows the legacy parser contract: async/sync decoded object with `width,height` or naturalWidth/naturalHeight matching the encoded header. Supply a real decoder in environments without browser Image. The callback is retained privately for subsequent validation; a thrown/rejected decode fails the entire commit. This layer never disposes caller decoded images, owns no GPU resources and does not cache them in serialized state. No cancellation API is provided; callers awaiting long validation must retain the previous displayed committed snapshot. Decoder callbacks must not mutate external state on which rollback depends.

## Task 7 additive mask contract (2026-10-24)

Task6 above is preserved as its historical foundation handoff; independent review is now Spec PASS / Quality PASS (`output/live2d-application-20261024/reviews/task-6-review.md`). The statements above that clips are unsupported and drawing delegates the whole pose describe Task6 only. Task7 now supports clips as follows. Grid/warp/deformers remain explicitly unsupported until Task8. No original artwork, legacy engine, UI, DB or SDK was changed.

`clipRelations` is a maximum-32 dense array of exactly `{sourcePartId,targetPartId,inverted:boolean}`. Both endpoints must be existing parts with rigs. Missing/self/duplicate directed pairs, directed clip cycles, extra fields, nonboolean inversion and mixed inversion for one target reject. Multiple distinct sources for one target are permitted. `setClipRelations` remains an atomic complete-field replacement; canonical hash already includes the array, so changes stale saved items and existing parse/editor/FIFO/undo/identity guards still apply. Removing clips restores ordinary rendering. No new saved-item hash migration occurs.

`evaluatePoseV3(doc,overrides?)` still returns the exact legacy-compatible pose shape when clips are empty. With clips it additionally returns `clipRelations`, `partIds` (all document part IDs), and `maskSources` (one draw record for every distinct source, including hidden sources and opacity-zero sources). Each draw record uses final document coordinates after the same extension-axis replacement and parent affine pipeline as ordinary drawing. Visibility affects ordinary display, including inherited visibility; it never disables mask-source evaluation. `maskSources.opacity` is the product of the source's own opacity and all parent opacities. Geometry is evaluated from the already displaced rigs, rather than applying bindings again. Hidden targets remain absent from ordinary draws. Blocked/unprepared parts still prevent drawing.

`drawPoseV3(canvas,pose,decodedAssets,{canvasFactory}={}):DrawResult` is synchronous. The return remains exactly `{width,height,drawnPartIds}`; IDs are ordinary displayed parts in layer order and exclude hidden mask-only sources. `decodedAssets` remains a caller-owned Map of decoded images. `canvasFactory(width,height)` must return a fresh Canvas2D surface with the requested size, distinct from the destination, other returned surfaces and decoded image assets. Outside a browser supply it explicitly. Browser defaults are OffscreenCanvas, then the destination's ownerDocument canvas creation. This dependency injection does not install a runtime dependency in the product.

Mask math is the own-engine contract approved by the coordinator, not a claim of Cubism equivalence. Each part's raw layer alpha is texture alpha multiplied once by that part's inherited opacity. Multiple distinct source layers use source-over union `a+b−ab` (two 0.5 sources give approximately 0.75 in their overlap), then the target uses destination-in or destination-out. Duplicate source→target pairs reject, so they cannot accidentally double the source. Acyclic A→B→C chains use B's effective alpha after its own clip from A, not B's original unmasked texture alpha. Hidden B remains available in that source cache. Task8 must preserve this effective-alpha pipeline when adding final warp geometry.

V3 owns full staging/composition and coverage normalization. It invokes legacy `drawPose` only for one affine triangle at a time: whole non-affine legacy draws would allocate hidden internal scratch without the v3 factory/release contract. Per-triangle color/coverage sums are normalized to a single union silhouette before inherited opacity is applied, preventing repeated opacity or alpha darkening on shared diagonals. The cache stores each source after its own clips; dependency sources finish before shared scratch is reused. The same routine renders sources and targets, allowing Task8 to extend the upstream coordinate pipeline without a separate mask geometry path.

Scratch accounting occurs before allocations: six reusable RGBA surfaces plus one RGBA cache per distinct source, and retained typed-array working set of 36 bytes/pixel (5-channel Uint32 sums + output/silhouette/two triangle RGBA readbacks). Formula: `width*height*(4*(6+sourceCount)+36)`, rejected above 128 MiB. The valid acyclic 16-part graph has at most15 sources, giving120 MiB at1024×1024 with headroom for small geometry/graph metadata. This bounds retained rendering scratch, not caller-owned decoded assets, native library process overhead or unreachable arrays waiting for garbage collection. All owned canvases shrink to1×1 and array/cache references are dropped in `finally` on success or error; borrowed destination/assets are never resized. The CPU host maps zero-sized canvases back to350×150, hence the portable1×1 release. Browser references are also dropped for garbage collection after shrinking. Completion of native backing-store reclamation, garbage collection or GPU release is not directly observed by this task.

Only a completed staging frame is copied to the destination in one `copy` drawImage call; validation, missing asset, allocation or rendering failure before that commit leaves prior destination pixels unchanged. The destination context is saved/restored. Caller evaluation errors occur before this drawing call and preserve the last displayed frame.

## Task7 fix round1 — T7-I1 precision correction

Independent review `reviews/task-7-review.md` rejected the first Task7 renderer for shared-diagonal RGBA re-quantization, including with no clips. This section supersedes the historical Task7 raster/120MiB paragraphs above; their exact original bytes remain preserved.

The corrected common paint routine checks whole-affine geometry with the same farthest-UV/largest-area basis and1e-4 tolerance as legacy. Whole-affine parts call legacy whole-part drawing directly on owned staging/cache surfaces, keeping native RGBA/opacity and avoiding its non-affine scratch path. The genuine non-affine case stays on the bounded v3 path: each triangle maps the whole original texture into scratch *without* clipping it to the triangle; coverage is rasterized separately. Float64 sums accumulate original sampled RGB×alpha×coverage and alpha×coverage; Uint32 coverage sums remain separate. A single union silhouette normalizes coverage. Only the completed raw layer is quantized to ImageData. That silhouette surface is then reused as the raw-layer image and one native draw applies the part opacity. Effective-alpha mask union/clip and the final native staging copy follow. Sources and targets use exactly this common routine; hidden/chain/opacity-once semantics are unchanged.

Scratch now has four shared RGBA surfaces (staging, union, triangle/ordinary destination, coverage/silhouette/raw-layer) plus one cache per source. Coverage, silhouette and raw layer deliberately reuse one surface in separate phases. Float64 RGBA sums use32bytes/pixel, Uint32 coverage4 and reusable output4. During a triangle read, sample RGBA4 and coverage RGBA4 are live, giving48bytes/pixel arrays. The two triangle readbacks leave scope before the silhouette RGBA4 is acquired; that later phase is44bytes/pixel. Preallocation checks `width*height*(4*(4+sourceCount)+48) <=128MiB`. At15 sources/1024² this is124MiB with4MiB headroom for small geometry/graph records. Arrays and all owned canvases still receive the existing finally reference cleanup/1×1 shrinking; completed host/GC/GPU reclamation is not measured.

Precision regressions compare actual RGBA exactly, without widening tolerances: five host texture alpha values1/16/64/128/255 ×opacity1/0.5; affine whole frames equal independent direct and legacy drawing; genuine non-affine shared-diagonal/interior samples equal independent native texture drawing; normal mask source and target roles both pass. Non-affine precision samples are inside the mesh, separating internal seams from exterior antialiasing. Fractional/rotated browser exterior-AA and production performance remain later gates. No alpha is discarded to hide the defect and no artwork changes occur.

## Task8 — two-axis grid keyforms and explicit parent warp chains

This section supersedes earlier “grid/warp unsupported” statements. Task6 and Task7 fix1 were independently approved before Task8 ownership. Task8 is source/CPU synthetic implementation, pending independent review and Task9 UI integration.

A grid binding has exactly `{id,partId,mode:'grid2d',parameterIds:[xId,yId],axes:[xKeys,yKeys],deltas:[vertexDeltaArray,...]}`. Each axis has2..8 strictly increasing finite keys, including the definition's minimum, default and maximum. The full Cartesian grid is mandatory (at most64 entries), with x-fast row-major indexing `yIndex*xKeys.length+xIndex`. Every cell stores a complete mesh delta array. The joint default key is all zero and cannot be changed. Both axes use bilinear interpolation; overflowing finite parameter spans are handled by half-scaled ratios. Each parameter may occur only once per part across all axis/grid bindings. Disjoint bindings sum once on base vertices and replace that part's legacy bindings; deleting the final extension binding still restores legacy fallback. Every keyed mesh is validated during parse, and the actual summed/interpolated mesh is checked again during evaluation, since valid keys alone do not guarantee valid intermediates.

`deformers` contains at most8 exact `{id,parentId,kind:'warp',rect:[x,y,width,height],columns,rows,deltas}` objects. `columns` and `rows` are integers2..8; deltas contain `columns*rows*2` finite numbers in x-fast row-major `[dx,dy,...]` order. Rect/lattice coordinates remain fixed in document space. Zero deltas preserve identity. Rect extents must be positive; geometry/displacements use the existing±1e7 numeric bounds. Missing parents, cycles, duplicate IDs, unknown fields, malformed dimensions/counts and folded/degenerate cells reject. Each bilinear cell checks all four Jacobian corners, and nonadjacent outer-boundary crossings/touches reject global self-overlap. The actual warped mesh triangle orientation is rechecked after every warp stage; this also catches straight mesh chords crossing several locally valid lattice cells.

**Coordinator-confirmed mapping rule:** `partDeformerIds` maps individual part IDs to an existing inner deformer ID or null. Missing/null means no warp. Part `parentId` supplies the existing affine and opacity inheritance only; it never implicitly inherits a parent's deformer mapping. After the complete part affine chain, the explicitly linked inner warp applies, followed by its `parentId` deformer ancestors, each exactly once. Task9's connected-part UI must explicitly map every desired child and mask source to the appropriate chain. Several parts may intentionally share one inner deformer. Inner and ancestor rects are fixed document rectangles; an incoming point outside any stage rejects evaluation rather than clamping. The upper/right boundary uses the last cell at interpolation fraction1.

The same memoized final-coordinate function transforms ordinary draws and hidden mask sources. Grid offsets precede affine evaluation; warps follow affine evaluation. Existing hidden/effective-alpha source chains, source-over union, inherited opacity once, immutable identity, rigHash, stale guards, FIFO/undo/redo and render staging are retained. `setBindings` and `setDeformers` already provide atomic validated batch replacement, with `setDeformers.value={deformers,partDeformerIds}`. Serialization/reparse and undo restore geometry and hashes. As in Task6, parse validates structure/key geometry and evaluation validates a requested combined pose; callers must evaluate successfully before replacing the displayed frame. An out-of-domain/folded requested pose throws before draw, preserving prior canvas pixels. Task9 must show that failure and retain its last rendered frame.

The Task7 fix1 raster implementation from `MAX_SCRATCH` through draw completion is byte-identical. Whole-affine legacy parity, unclipped original texture sampling with separate Float64 coverage accumulation for non-affine geometry, opacity once, staging/factory ownership and retained scratch≤124MiB under128MiB remain unchanged. Added geometry metadata is small and has no per-pixel buffers. Host/GC/GPU reclamation and caller-owned images remain outside the retained-scratch bound.
