## 실제 2D 움직임의 최소 선행사항과 빠진 결정

1. **한 캐릭터의 수동 소재부터 고정:** 1024px 정면 상반신, 최대16부위 안에서 눈·입·호흡에 필요한 RGBA 소재와 배경을 준비한다. 이동으로 드러나는 가림 영역은 직접 그린/승인된 소재로 보완하고, 없으면 그 이동을 막는다. Codex 개통·새 모델 선정은 이 수동 소재 움직임 검증의 선행조건이 아니다. 최종 제출의 SDK 시연 의무는 별도로 유지한다.
2. **공통 문서와 소유 경계 확정:** 소재 ID/내용 해시·원본 revision·소재 좌표·부모/z순서·메시/UV/삼각형·키폼·파라미터·시간 곡선·리그 호환 해시를 하나의 계약으로 고정한다. 브라우저 렌더와 Python 자산/출력 중 어느 쪽이 프레임을 만들고 누가 저장하는지 먼저 정한다. 서버 저장 API가 필수인지도 결정해야 한다.
3. **실제 변형을 먼저 입증:** 같은 topology/UV에서 중간 파라미터의 정점 형태와 시간 변화를 렌더한다. 새 추론 0회, 알파/앞뒤/경계·잘못된 리그 재사용 차단을 확인한다. 정지 편집의 ‘마스크 밖 픽셀 0오차’와 움직여 달라지는 장면 합성의 검증 기준은 구분한다.
4. **작은 수직 경로로 출력·복원 연결:** 실제 변형→48프레임→저장→재개에서 크기·알파·프레임 순서와 동일 상태를 확인한다. `t=i/24, i=0..47` 같은 시간 규칙, 반복 끝점·파일명·패키징은 구현 전에 명시한다. 실패 시 원본/기존 프로젝트를 유지하고 실패를 표시하며, 미리 만든 영상으로 대체하지 않는다.

계획서 앞부분의 ‘생성·수정을 먼저’와 최신 사용자의 ‘실제 2D 움직임 우선’ 사이에는 **착수 순서 재정렬**이 필요하다. Codex 4~5일 견적을 움직임 개발의 대기 조건으로 두지 않는다. 총괄은 위 데이터/출력·저장 경계를 확정해 부위/변형 담당과 백엔드 담당에 배정하고 통합 판정을 맡는다.

이번 변경은 이 인계 파일뿐이다. 새 조사·웹·설치·모델/GPU·테스트 실행/변경·생산 코드·새 채팅/에이전트는 없었다. D 드라이브 접근은 가능했다.
