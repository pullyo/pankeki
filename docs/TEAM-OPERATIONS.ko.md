## 최신 사용자 승인: 움직임 설계 채택·기존 팀 구현

사용자는 움직임 설계에 이어 [실행계획](superpowers/plans/2026-10-20-motion-first-implementation.md)을 “계획 확인, 작업팀 구현 시작”으로 승인했다. 현재는 **설계·계획 승인 / 프론트·기술·기능·디자인에 실제 구현 지시 전달 / 첫 코드 변경 확인 대기**다. T1~9·모듈/API·파일 소유권·검증/인계를 유지하고 실제 첫 코드 변경·검증·통합 완료를 [기능 추적표](product/feature-delivery-tracker-20261020.ko.md)로 분리해 기록한다. 설계/계획 재승인을 요청하지 않는다.

## 2026-10-20 최신 착수 요청: 실제 2D 움직임 우선

사용자가 실제 눈·입·호흡 변형 기능을 먼저 요청했고, 이어 계획 누락과 실제 착수 여부를 확인했다. 기존 계획을 삭제하지 않고 [누락 점검](product/plan-gap-audit-20261020.ko.md)에 현재 구현/미구현/정의 충돌을 기록한다. [움직임 우선 설계](superpowers/specs/2026-10-20-motion-first-design.md)는 검토본이며 현재 상태는 **담당 읽기 검토 중, 움직임 코드 미착수**다. 총괄이 구현 착수를 지시한 것처럼 보고하지 않는다. 다음 코드 단계는 기존 스킬의 작성 설계 검토와 실행계획 검토 절차를 따른다. 새 채팅·하위 에이전트 없이 기존 담당을 사용한다.

## 2026-10-20 최신 제품 우선순위

사용자는 캐릭터의 **생성과 수정을 편하게 하는 것**을 내세울 장점으로 만들도록 요청했다. 제품 설명·첫 시연·사용성 검토의 중심을 짧은 입력/내 그림 → 후보 비교 → 원하는 부분 수정 → 적용·되돌리기 → 저장·재개에 둔다. [공통 제작 기획의 최신 사용자 방향](product/character-workflow-live2d-plan.ko.md#최신-사용자-방향-생성과-수정을-편하게)에 현재 기반·추가 과제·검증 기준을 기록했다. 기존 따뜻한 UI를 재사용하고 Live2D 부위·움직임은 후속 제작을 돕는 확장으로 연결한다. 마스크 밖 픽셀 보존과 생성 영역 안의 인물 동일성을 구분한다. 새 조사·다운로드·코드 구현이나 미구현 기능 완료를 뜻하지 않는다.

## 2026-10-20 14:00 KST 최신 일정

사용자는 기간 단축과 **10월30일 내부 완료**, 날짜별 일정 계산·계획 작성을 요청했다. 최신 계획은 [10월30일 압축 일정](product/submission-plan-20261030.ko.md)이며, 10/28 18시 기능 동결·10/29 검수·10/30 18시 내부 완료를 목표 시각으로 제안한다. 아직 만들지 않은 기능의 완료나 무조건적인 납기 약속을 뜻하지 않는다. 총괄 아지는 제품 구현 코드를 작성하지 않고 기존 팀의 배정·계약·검수·통합을 맡는다.

현재 실행 중인 승인 작업은 다중 모델 다운로드·비교와 그 분리 실행환경 준비이며, 따뜻한 UI 구현/화면 검증은 완료됐다. 기존 분석 단계의 포괄적 다운로드 금지는 이 승인 작업에 적용하지 않는다. Codex 실제 대화와 부위·메시 엔진은 아직 구현 전이다. 관련 다음 코드 작업은 압축 범위와 담당별 인터페이스 검토를 거쳐 구체화하며, 일정표만 보고 완료나 착수로 해석하지 않는다. 새 채팅/하위 에이전트 없이 자료와 테스트를 재사용한다. 아래 이전 재개 기록은 최신 인계와 다르면 과거 기준으로 읽는다.

2026년 10월 20일 한국시간에 사용자가 인수인계 확인, 현재 채팅의 총괄 역할, 담당 작업 채팅 추가와 역할 분담을 요청했다. 총괄의 이름은 사용자 지정에 따라 아지다. 현재 총괄 채팅은 `아지 총괄·Pankeki`이며 사이드바의 `아지 총괄` 구역에 별도로 배치했다. 아지는 진행 상태와 검증 결과를 취합하고 공통 계약 및 통합을 관리한다.

## 최신 작업과 자원 사용

사용자는 Live2D, PhotoCraft, ComfyUI를 분석해 유용한 기술과 Pankeki 적용 아이디어를 정리하도록 요청했다. 현재 코드 구현보다 근거가 있는 아이디어 3~5개의 선별이 우선이다. 도구별 기술 분석은 Live2D를 기술·모델 리서치 담당, PhotoCraft를 프론트엔드 담당, ComfyUI를 백엔드 담당이 맡는다. 아지가 교차 아이디어와 우선순위를 종합한다.

사용자는 토큰을 과도하게 사용하지 말라고 요청했다. 새 채팅과 하위 에이전트 생성은 중단하고, 조사 파일·문서 범위를 좁히며 완료된 테스트와 조사를 반복하지 않는다. 다른 담당은 기존 산출물을 인계한 뒤 대기한다. 자동 완료 확인은 30분 간격으로 설정했으며, 세 도구의 1차 분석과 디자인 보고서가 완료돼 반복 확인을 종료했다.

사용자가 필요한 GitHub 도구의 설치와 사용, `morluto/rea`의 설치·적용을 명시적으로 요청했다. 이에 따라 앱 및 공식 Comfy SDK의 전용 가상환경을 복원하고 REA 6.7.0과 npm 11.16.0을 `.tools/rea`에 설치했다. REA의 Codex 등록과 전용 스킬 설치도 완료했다. 현재 분석은 CLI로 즉시 수행할 수 있으며, 등록 상태와 현재 세션의 MCP 연결 여부는 구분한다. 세부 증거는 `docs/handoffs/resume-qa-tooling.md`와 `work/team-resume/tooling/`을 따른다. 모델 가중치나 전체 CUDA 환경의 추가 복원은 이 도구 설치 작업에 포함하지 않았다.

## 첫 작업의 완료 기준

기능 담당은 저장된 결과와 실제 코드를 근거로 이미지 품질의 잔여 원인을 정리하고, 이번 환경에서 재현 가능한 결함이 있으면 가장 작은 수정과 적절한 회귀 검증을 남긴다. 결함이 확인되지 않으면 생산 코드를 임의로 바꾸지 않고 다음 품질 실험의 가설과 판정 기준을 작성한다.

디자인 담당은 밝고 정돈된 채팅 중심 화면과 큰 캔버스를 유지한다. 사용 가능한 화면 확인 수단으로 실제 구현을 점검한다. 근거가 있는 화면 결함은 담당 소스에서 수정하고, 화면 검증이 불가능한 항목은 인계에 남긴다. 선택된 로고와 기존 후보 비교, 마스크, 프로젝트 저장 기능은 유지한다.

환경 담당은 실행 파일과 Python 버전, GPU 및 메모리, 모델과 venv 존재 여부, 8188/8189/8190 포트 상태를 현재 기준으로 확인한다. 가능한 기존 테스트를 실행해 통과, 실패, 환경 부족을 구분하고 명령과 로그를 보존한다. 실행 중인 다른 작업이 있으면 코드 변경 시점을 함께 기록해 테스트 기준을 명확히 한다.

프론트엔드 담당은 생성과 취소, 늦은 응답, 모델 전환, 후보와 프로젝트의 저장·복원 상태를 확인한다. 실제 모델이나 서버가 없는 항목은 기존 테스트와 저장 자료로 가능한 범위만 검증한다. 미연결 대화에 가짜 응답을 추가하지 않는다. 디자인 담당의 HTML/CSS와 기존 DOM 계약을 유지한다.

각 담당은 완료 사항, 변경 파일, 검증 명령과 결과, 남은 문제, 총괄에게 필요한 결정을 담당 인계 파일과 채팅 최종 답변에 남긴다. 총괄이 담당 채팅 상태와 파일을 읽어 결과를 취합하므로 별도 채팅에 자동으로 메시지를 보낼 필요는 없다.

기획 담당은 기존 사용자 결정을 새로운 승인으로 취급하지 않고 유지한다. 대회나 외부 서비스의 현재 요건을 인용할 때는 공식 원문을 확인한다. 추가 다운로드 없이 가능한 차별화 과제를 우선 제안하며, 생산 코드는 수정하지 않는다.

기획팀은 세 담당으로 나눈다. 제품 기획은 요구사항과 공식 제출 요건, 기술 리서치는 현재 환경에서의 모델·워크플로 가능성, 사용자·경쟁제품 리서치는 공개된 사용 흐름과 차별화 근거를 맡는다. 인터뷰나 사용자 조사를 실제로 수행하지 않았다면 그 결과를 만들어내지 않는다. 외부 제품의 현재 기능과 모델 사양은 공식 원문을 확인하고 확인일을 남긴다. 모든 제안을 바로 구현 지시로 취급하지 않고 총괄이 우선순위와 범위를 조정한다.

출시 담당은 준비 자료와 출시 가능 여부의 근거를 작성한다. 원격 게시, GitHub push, 제출, 타인에게 메시지 보내기는 이번 배정에 포함하지 않는다. 현재 소스의 어떤 부분이 공개 스냅샷과 다른지, 어떤 검증이나 설명이 필요한지를 총괄에게 인계한다. 환경 검증 담당의 로그는 읽기만 한다.

## 작업 순서

1. 복원한 소스와 최신 인수인계를 읽고 현재 환경을 확인한다.
2. 기능, 디자인, 환경 검증을 각 소유 범위에서 병렬로 진행한다.
3. 총괄이 결과를 검토하고 재현되는 결함과 품질 실험의 우선순위를 정한다.
4. 필요한 소스 통합 후 한 번 빌드하고 해당 변경에 맞는 검증을 수행한다.
5. 실제 이미지 생성은 모델과 실행 환경이 갖춰지고 검증할 가설이 정해진 뒤 진행한다.

새 모델이나 대규모 패키지 다운로드, 저장된 9개 비교의 자동 재실행, MoE 설치는 첫 작업에 포함하지 않는다. 저장된 결과와 자동 테스트의 성공을 이미지 품질 승인으로 표시하지 않는다. 공개 GitHub 스냅샷으로 최신 복원 소스를 되돌리지 않는다.

## 진행 상태

복원 검증과 역할별 채팅 8개 배정을 완료했다. 작업팀은 코딩 3명, 기획·리서치팀은 3명, 검수·출시팀은 2명이며 아지가 별도 총괄이다. 세 도구의 1차 분석과 아이디어 종합을 완료했고, 최종 보고서는 `docs/product/app-design-plan.ko.md`다. Live2D 담당의 별도 출력도 공통 문서 경로로 수집했다. 기존 디자인 결함4개의 최종 HTML 통합과 SDK 브리지12개 재검증을 확인했다. 제안한 신규 부위·이력 기능은 구현 전이다. 현재 역할과 보고서 경로는 `work/team-resume/coordination.json`을 따른다.
