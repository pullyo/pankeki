# 정밀 색상 변경 — 총괄 통합 검토

검토일: 2026-10-23. **기존 부분 수정 화면의 색상 변경 모드를 구현·검수·통합했다.** 고정 마스코트의 목도리를 빨강으로 바꾸면서 천의 길이·겹침·주름·술·선의 위치를 유지하는 결과를 총괄·UX·QA가 직접 비교했다. 기존 AI 부분 수정은 별도 작업으로 유지한다.

## 반영한 동작

디자인 → 작업 **색상 변경** → 영역 칠하기/마스크 불러오기 → 바꿀 색 선택 또는 HEX 입력 → **색상 적용** 순서다. 기준 색은 자동 추정 또는 직접 지정하고 색 범위로 조절한다. 원본 후보를 보존하고 새 후보 한 개를 만든다. 잘못된 HEX는 요청 전에 거부하고, 빈 마스크·일치 색 없음·동일색은 변경 없음으로 표시한다.

원본 좌표에서 OKLab 색·톤을 변환하고 원래 색의 범위만 선택한다. 기존 pixel composite를 사용하며 재생성·리사이즈·형태 이동을 하지 않는다. 색상 작업에는 이미지 모델·Comfy·GPU가 필요 없다. 실제 metadata도 `kind=local_recolor`, `model_calls=0`으로 기록한다. 일반 생성과 자유 AI 부분 수정의 모델·그래프·기본값은 유지했다.

로고·작업 메뉴 11개·PC 대화 작업 공간·후보 비교·프로젝트/PNG 경로를 유지했다. 최종 1440×900 화면에서 편집 후보 비교 중 생성용 스타일 행이 숨겨지는 것도 확인했다.

## 검수 중 발견해 수정한 문제

- 새 request 필드를 후보·v1/v2 문서에 보존하도록 allowlist를 확장했다. CPU kind도 후보 metadata에 유지했다.
- backend의 skipped는 문자열인데 프론트가 true만 확인해 무변경을 성공으로 표시했다. 실제 사유 문자열로 실패 회귀를 만든 뒤 결과·대화·갤러리·비교·보드·복원 표시를 맞췄다.
- 내장 브라우저에서 기존 data-URL PNG 저장이 두 번 timeout한 반면 프로젝트 Blob 저장은 성공했다. PNG 클릭을 기존 Blob 저장 함수로 연결하고 원래 data URL·MIME·파일명·바이트를 보존했다. 최종 실제 PNG 다운로드 성공으로 재확인했다. 프로젝트·보드·모션의 다운로드 함수는 바꾸지 않았다.
- 편집 후보 비교 화면에 생성 스타일이 다시 노출되던 표시를 숨기고 실제 화면을 다시 확인했다.
- 마지막 경계 검사에서 257×257 이미지의 직접 지정한 빨강 1픽셀이 대표색 표본에서 빠져 무시되는 문제를 재현했다. 수동 기준색의 표본 일치가 없으면 전체 해상도에서 다시 선택하도록 보정했다. 실제 부재색은 계속 변경 없음이며, 회귀 2개와 QA의 RGB/RGBA 함수·Engine 독립 검사를 추가했다.

기존 자동 복원은 사용자가 먼저 작업하면 restore epoch를 취소한다. 최초 검수에서 새로고침 직후 바로 화면을 이동해 이 조건이 작동했다. 재검수에서는 입력하지 않고 복원 완료를 기다린 후 후보 5개·색상 설정·복원 안내를 확인했다. 저장 데이터 유실이나 새 복원 결함으로 보고하지 않는다.

## 검사와 변경 범위

- 총괄의 최종 Python 전체: **147건, 127통과·Windows 전용 20skip·실패 0**.
- 총괄의 최종 JS 11파일: **177건, 175통과·1skip·1TODO·실패 0**. 실제 canvas pixel 검사는 비활성인 suite이며 실제 이미지/브라우저/PNG 검증을 별도로 수행했다.
- Ruff E9/F63/F7/F82 오류 검사 0. ast-grep로 모델 경로 이전의 CPU 분기를 구조 검색했다. 기본 전체 lint가 모두 깨끗하다는 주장은 아니다.
- 빌드 성공, 실행 중 HTML과 최종 빌드 SHA 일치. 마지막 경계 보정까지 포함한 backend 지문 `bd1e0cb5ed846ab6ef6b2d9ea7d8b7a67ad77deb612498d06d29ac9e5229c200`로 기본 Mac 런처를 정상 재시작했다. 소스 변경 감지 guard는 유지했다.
- 최종 서버의 실제 HTTP 대조 2건: `f1401102b707437aab49518ce7d94e63`의 자동 기준색 목도리 PNG는 검수한 UI/저장 PNG와 전체 바이트가 같다. `e1f4628e84754a268da222da5ec2bb96`은 직접 지정한 빨강 1픽셀만 정확히 초록으로 바꾸며 나머지 66,048픽셀·전체 alpha가 같다. 둘 다 모델 호출 0이며 최종 소스 지문과 recipe가 일치한다. `runtime/macos/recolor-quality/integration/final-runtime-proof.json`에 기록했다.
- 새 제품 모듈은 `pankeki/recolor.py`. 기존 파일 변경은 engine.py와 app/profiles/redesign JS·CSS/template, 생성 index다. 초기 추적 31파일 중 24파일은 불변이다. 런처·runtime config·모델 preset·Comfy·모션/렌더/출력 모듈은 유지했다. 관련 신규/기존 테스트와 문서·증거는 별도 변경이다.
- 과거 전용 모델 실험 테스트는 과거 실제 baseline source 지문에 묶여 있었다. 테스트용 합성 baseline을 격리하고 stale-product 거부 검사를 추가했다. 실제 과거 baseline·실험 스크립트의 guard는 유지했다.

## 남은 한계

마스크와 기준 색 범위에 따른 색 변환이며 의미 기반 물체 분할은 아니다. 같은 색의 다른 물체가 마스크 안에 있으면 함께 바뀔 수 있어 영역/기준색/범위를 조절해야 한다. 마스크 밖은 정확히 보존하므로 좁은 마스크 밖 원래 색이나 feather 경계의 혼합색을 임의로 지우지 않는다.

빨강 고정 사례는 형태·주름·술·명암 위치와 주변 보존을 수용했다. 흰색/검정은 톤을 옮기므로 원본과 동일한 밝기·대비를 보장하지 않으며 흰색의 미세 잔류색·검정의 어두운 주름 가독성 한계가 관찰됐다. RGBA는 작성한 합성/파생 입력으로 alpha 보존을 검증했으며 자연 이미지의 모든 반투명 소재에 대한 시각 품질을 일반화하지 않는다.

기존 생성/자유 AI 편집·모션/출력의 코드 회귀는 통과했으나 이번에 새 SDXL 추론이나 48프레임 전체 UI 출력을 다시 실행한 것은 아니다. 정밀 색 변경은 새 색상 변경 모드의 수용이며, 자유 생성형 편집이 모든 색 지시를 정확히 따른다는 결론으로 확대하지 않는다.
