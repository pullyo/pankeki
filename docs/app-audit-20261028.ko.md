- **[M] `jobs.py:242-257` → `:275-284`** 종료 상태를 두 번 영속화하는 사이에 같은 session의 `submit()`이 들어오면 revision이 전진해 두 번째 transition이 거부되고, 메모리 job은 `failed`로 바뀌지만 DB·`complete.json`·캐시는 `succeeded`. 메모리와 영속 상태 불일치.

- **[M] `server.py:335, :253`** `do_POST`/`do_GET`의 예외 필터가 좁아 RuntimeError(`job_store.py:117/133/166`)·MemoryError·RecursionError(깊은 JSON deepcopy)는 응답 없이 소켓이 끊긴다. 실제 로그에도 `send(400)` 중 BrokenPipeError 트레이스백 15건이 그대로 남아 있다.

## 6. 잘 되어 있는 점

- 보안 경계가 실제로 적용된다: 백엔드 127.0.0.1/Host/Origin/JSON/32MiB/ID 정규식/symlink 검사, Electron 하드닝(contextIsolation·sandbox·CSP 해시·권한 전부 거부·IPC allow-list), 파일 경로가 렌더러·외부 모델에 노출되지 않는 opaque ID 설계.
- "가짜 성공"을 피하는 문화가 일관된다: 테스트 통과≠GPU 성공, 측정 안 한 값은 null, 제출 불확실·취소 미확인·orphaned을 별도 상태로 구분, 자동 재시도 없음, 결과 무결성 SHA256 재검증, 마스크 밖 픽셀 오차 0을 서버·MCP 양쪽에서 검증.
- 프론트 상태 경합 방어(`serial`/`sourceRevision`/`maskRevision`/`editEpoch`)와 입력 검증(`profiles.js`)이 꼼꼼하고, 접근성 기본기(스킵 링크, aria, `<dialog>`, IME Enter 처리, reduced-motion)가 갖춰져 있다.
- 빌드가 결정적이고(재빌드 SHA 동일) 토큰 미해결·순서 오류를 실패로 잡는다.
- Mac 실행기가 공백 포함 경로·모델 부재·포트 점검·자식 정리를 처리하고, 기존 서버를 죽이지 않고 재채택한다.
