## 제품의 한 문장

**Pankeki는 오리지널 캐릭터를 만들고, 원하는 부분을 고치고, 표정·움직임과 편집 가능한 프로젝트로 이어 가는 창작 작업실이다.**

이는 전달할 제품 방향이다. 생성된 평면 이미지에서 부위가 자동으로 분리되거나 자동 리깅되는 기능은 현재 검증되지 않았다. 움직임에 준비한 분리 PNG와 수동 설정이 필요한 구간은 시연과 README에서 그대로 설명한다.

기존 로고·11개 메뉴·채팅형 작업 공간·실제 생성/마스크/후보/프로젝트/편집/움직임/출력을 보존한다. 수상을 위한 새로운 광범위 기능 목록보다 이 흐름의 품질·연결·재현성을 우선한다.

## 현재 강점과 가장 큰 약점

이미 검증한 강점은 최신 UI에서 실제 SDXL 생성, 원본·마스크 경계 보존, 실제 저장 후보 기록, 프로젝트 복원과 별도 편집·모션·프레임 출력 기반이다. SDXL 최종 UI 생성26.25초, 마스크 밖 RGB/알파 오차0 등은 해당 기존 실행 기록의 결과이며 일반적인 속도나 모든 입력의 품질 보장이 아니다.

가장 큰 약점은 **수정 영역 안의 지시 준수와 형태 유지 품질**이다. 복원 기록에서 낮은 강도는 기존 파란색이 남고 높은 강도는 색과 형태가 함께 바뀌었다. 모델이 작업을 완료했다는 사실과 사용자가 원하는 수정이 됐다는 판정을 분리한다.

다음은 실제 사용자 고유 소재를 통한 연속 시연, 최종 Mac의 PNG/ZIP 실물 확인, 다른 환경에서 설치·실행 재현이다. 개별 기능 검증을 하나로 이어지는 작품 제작 완료로 확대하지 않는다.

## 총괄의 내부 수용 기준

아래 기준은 주최 측 공식 배점이 아닌 우리 팀의 개발·검수 기준이다.

1. **수정 결과가 설득력 있을 것.** 소수의 고정된 오리지널 입력으로 동일 조건의 before/after를 비교한다. 지시 반영, 형태·캐릭터 특징, 경계, 원본 밖 RGB/알파 보존, 시간·실패를 각각 기록한다. 불리한 결과도 남기며 합격할 수 없는 편집 약속을 기능 설명에 넣지 않는다. 초기 평가는 기존 SDXL부터 하고 모델 교체 여부는 그 결과로 판단한다.
2. **한 작품이 끝까지 이어질 것.** 생성/원본 → 후보 선택 → 마스크 수정 → 저장/재개를 실제 앱에서 연결한다. 표정/움직임 확장은 준비된 자기 분리 소재를 명시해 실제 재생과 출력까지 보여 준다. 모든 단계가 한 번에 되는 척 편집하지 않는다.
3. **실제로 다시 실행할 수 있을 것.** 모델/환경/명령·workflow와 결과를 대응시키고, 깨끗한 환경에서 안내만으로 시작할 수 있는지 검증한다. PNG/ZIP은 다운로드 버튼 동작을 넘어 실제 파일·알파·프레임을 독립 판독한다.
4. **2분 안에 가치가 보일 것.** 문제·완성 결과를 먼저 제시한 뒤 실제 조작과 ComfyUI 활용 방식을 보여 준다. 추론 대기를 줄여 편집한 경우 대기/속도 변경을 명시한다. 기능·품질·자동화 범위를 실제 검증과 일치시킨다.
