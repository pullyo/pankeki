# Pankeki 앱 디자인과 구성 제안

2026년 10월 20일 한국시간 · 아지 총괄 보고

Pankeki는 **대화로 캐릭터를 구상하고, 큰 캔버스에서 후보를 비교하며, 선택한 부위를 안전하게 다듬는 캐릭터 디자인 작업실**로 구성한다. 기존 밝은 화면과 팬케이크 로고를 유지하고, Live2D의 부위 관리, PhotoCraft의 편집 이력, ComfyUI의 실행 정보를 연결하는 방향을 권한다. 아래의 신규 기능은 구현 전 제안이다.

## 화면 구성

화면은 프로젝트 하나에 집중하는 작업실을 기본으로 한다. 데스크톱에서는 왼쪽 대화, 중앙 캔버스, 오른쪽 작업 패널을 사용한다. 1440px 화면의 설계 기준은 왼쪽 약300px, 오른쪽 약280px, 중앙 가변 폭이다. 실제 비율은 기존 화면에서 검증하며 좁은 화면에서는 오른쪽 패널을 접는다.

| 구역 | 구성과 역할 |
| --- | --- |
| 상단 프로젝트 바 | 로고, 프로젝트 이름, 저장 상태, 새 작업·저장·불러오기·보드 내보내기. 이미지 PNG 저장과 편집 가능한 프로젝트 저장을 구분한다 |
| 왼쪽 대화와 요청 | 캐릭터 설명·참고 이미지·수정 요청. 실행 전 원본 후보, 바꿀 부위, 바꿀 속성, 유지할 조건을 짧은 카드로 확인한다. 모델·샘플링 설정은 접힌 보조 영역에 둔다 |
| 중앙 큰 캔버스 | 선택한 후보를 가장 크게 표시한다. 보기·부위 선택·수정 전후 비교로 전환하고 필요한 브러시·지우개·마스크 표시만 가까이에 둔다. 현재 편집 원본과 변경 범위를 함께 표시한다 |
| 오른쪽 작업 패널 | `후보`, `부위`, `기록` 탭으로 나눈다. 후보는 비교·기준 선택·재편집, 부위는 이름 붙인 마스크와 잠금, 기록은 수정 전후와 되돌리기를 맡는다 |
| 작업 상태 | 해당 후보의 준비→생성→마무리→완료를 실제 정보가 있을 때 표시한다. 결과 재사용·실패·취소·진행 정보 없음은 각각 다른 상태로 표시한다 |

모바일은 기존 `대화 / 결과` 전환을 유지한다. 결과 화면에서는 캔버스를 먼저 보여주고 후보·부위·기록을 접을 수 있는 영역에 둔다. 390px에서도 첨부·수정·저장과 키보드 초점 이동이 가능해야 한다.

## 핵심 사용 흐름

사용자는 캐릭터 설명이나 원본 이미지를 넣고 원하는 조건을 정리한다. 같은 조건에서 만든 두 후보를 비교해 기준을 고른 뒤, 수정할 부위를 칠하고 한 가지 목표를 지정한다. 예를 들어 “후보1의 장갑만 청록으로, 얼굴과 망토는 유지”라는 요청에서 원본·마스크·유지 조건을 확인한 후 실행한다. 결과를 부모 후보와 비교하고 사람이 요구 충족 여부를 확인한 뒤 이미지, 프로젝트 또는 전달용 보드를 저장한다.

대화 모델이 연결되기 전에는 미연결 상태를 표시하고 실제 이미지 생성·수정 입력을 제공한다. 대화 응답을 만들어 채우지 않는다. 모델 연결 후에도 제안과 실제 변경 실행을 구분한다. 생성 완료, 마스크 밖 보존, 사용자가 원하는 색·재질 충족은 서로 다른 판정이다.

## 세 도구에서 가져올 아이디어

| 우선순위와 아이디어 | 분석 근거 | Pankeki에서의 구성 | 예상 난도와 조건 |
| --- | --- | --- | --- |
| 1 부위별 수정과 잠금 | Live2D의 파츠 ID·계층·선택·잠금 | 장갑·망토·가방처럼 수동 마스크에 이름을 붙여 다시 선택한다. 잠근 영역은 수정 범위에서 제외한다 | 중상. 마스크 저장과 원본 연결, 프로젝트 형식 확장이 필요하다 |
| 2 편집 체크포인트와 되돌리기 | PhotoCraft의 문서 편집 트랜잭션·이력·별도 마스크 상태 | 마스크 획을 되돌리고, 저장 후 같은 후보·부위에서 이어서 편집한다. 승인한 후보는 속성별로 묶는다 | 중상. 이미지 참조 재사용·저장 용량·구버전 호환을 함께 설계한다 |
| 3 후보별 실제 진행 단계 | ComfyUI의 노드 실행·진행 이벤트 | 현재 후보가 준비·생성·마무리 중인지 표시하고 결과 재사용을 구분한다 | 중. SDK가 실제 전달하는 이벤트부터 확인한다 |
| 4 경계 부드러움 재조정 | ComfyUI의 의존성 분리와 PhotoCraft의 마스크 속성 분리 | 검증된 부분 수정 결과에서 경계만 다시 합성한다. 해당 조절에는 새 추론을 요청하지 않는 경로를 검토한다 | 중. 원본·마스크·추론 결과의 동일성과 픽셀 보존을 검증해야 한다 |
| 5 화면과 대화의 공통 명령 | PhotoCraft의 명령 ID·인자·실행 가능 검사 | 후보 선택·비교·부위 수정이 같은 검증 경로를 사용하게 한다. 늦게 도착한 제안이 다른 프로젝트를 바꾸지 않게 한다 | 중상. 실제 대화 연결과 명령 계약이 선행한다 |

이 표의 난도는 설계 단계의 상대 평가다. 색·소품·재질의 생성 품질이나 편집 시간 개선은 아직 실측하지 않았다. 실제 눈·입 보간이나 머리카락 물리는 분리된 레이어·메시·키폼·리깅이 필요한 후속 과제로 둔다. PNG 후보 전환을 Live2D의 연속 변형으로 취급하지 않는다.

## 시각 디자인과 조작 원칙

기존의 흰 패널, 밝은 회색 배경, 짙은 회색 글씨, 올리브색 강조(`#556b42`)를 유지한다. 팬케이크 로고를 사용하고 캐릭터 이미지가 화면에서 가장 강하게 보이게 한다. 중요한 실행 버튼은 현재 작업에 맞게 ‘후보 만들기’ 또는 ‘선택 부위 수정’으로 표시한다. 긴 설정은 기본 화면을 덮지 않도록 접고, 위험한 범위 변경과 원본 교체는 실행 전에 드러낸다.

오류를 성공 색으로 보이지 않게 하고, 로딩·미연결·대기·실패를 구분한다. 포커스 표시, 버튼 이름, 모바일 첨부, 비교 후 초점 복귀를 유지한다. 진행률을 알 수 없으면 단계만 표시하며 추정 퍼센트를 만들지 않는다.

## 첫 구현 범위와 검수 기준

첫 구현은 **이름 붙인 수동 마스크, 마스크 되돌리기, 저장 후 편집 재개**로 묶는 것을 권한다. 현재 프로젝트는 마스크를 저장하지 않으므로 저장 계약을 먼저 정하고, 기존 version1 프로젝트를 계속 불러올 수 있어야 한다. 이어서 실제 진행 단계와 부모·자식 비교 및 수동 검수 기록을 연결한다. 경계 재합성과 실제 대화 명령 연결은 그다음에 검토한다.

| 담당 | 첫 구현에서 맡을 범위 |
| --- | --- |
| 백엔드·이미지 처리 | 원본·마스크·결과 참조, 편집 범위 검증, 원본 밖 픽셀 보존, 이후 재합성 경로 |
| 프론트엔드 | 부위 선택·잠금, 마스크 이력, 프로젝트 저장·복원, 늦은 응답 제외 |
| 디자인·사용성 | 오른쪽 탭과 선택 상태, 실행 전 확인 카드, 모바일과 키보드 흐름 |
| 검수 | 다른 원본에 마스크 오적용 방지, 저장·재개, 구버전 호환, 실제 요청과 화면 일치 |
| 기획과 아지 총괄 | 사용자 효과·수용 기준 정리, 범위 조정, 결과 검토와 통합 |

완료 기준은 부위와 원본의 연결이 맞고, 잠금이 지켜지며, 저장 후 마스크와 이력이 복원되고, 마스크 밖 RGB 및 원본 알파가 보존되는 것이다. 생성된 색·재질의 의미 품질은 별도 이미지 검토로 판단한다. 이 보고서는 제품 코드의 신규 구현 완료를 뜻하지 않는다.

## 분석 범위와 현재 상태

Live2D는 설치된 Cubism5.3.04의 PE·JAR 정적 정보를 REA로 확인하고 공식 매뉴얼·공개 SDK를 분석했다. 이 검사로 Editor의 내부 변형 알고리즘이나 실제 화면 동작을 확인한 것은 아니다. PhotoCraft는 공식 저장소 commit `3a896a5efca8c69ab7c00f0fd0160adfd76a6ae3`의 핵심8개 소스, ComfyUI는 로컬 commit `8f04fd6ecf4a548937971e840af2a985529fab76`의 핵심5개 소스를 기준으로 삼았다. 세 도구의 1차 분석은 완료했다.

기존 UI에서 발견한 접근성·오류 표시 결함4개는 별도 담당이 수정해 최종 HTML에 빌드했다. 이 제안의 부위·이력 탭이나 새로운 저장 형식은 아직 구현하지 않았다. 앱·공식 SDK 환경과 REA는 설치됐으며 모델 가중치·GPU 생성 환경의 전체 복원과 새 이미지 품질 실험은 수행하지 않았다.
