# Pankeki 실제 2D 움직임 우선 설계

2026-10-20 KST · 아지 총괄 · 사용자 설계·실행계획 승인 / 기존 작업팀에 구현 지시 전달

사용자가 “그 설계대로 진행해. 작업팀에 맡겨서 2D 움직임부터 구현하고 빠뜨린 기능들도 빠짐없이 챙겨줘”라고 승인했다. 실행 방식은 기존 작업팀 분담이며 총괄 직접 코딩·새 채팅/하위 에이전트를 뜻하지 않는다. 첫 undo 이력은 실행 중에만 유지하는 범위를 포함해 승인된 설계로 기록한다. [실행계획](../plans/2026-10-20-motion-first-implementation.md)과 [전체 기능 추적표](../../product/feature-delivery-tracker-20261020.ko.md)를 연결한다.

## 목적과 현재 상태

사용자는 Live2D처럼 2D를 움직이는 기능부터 요청했다. 첫 결과는 **자신의 준비한 2D 부위를 가져와 눈·입·호흡을 직접 조절하고, 반복 동작을 재생·정지하며 저장 후 이어 여는 것**이다. 총괄은 구현 코드를 작성하지 않고 기존 담당의 배정·계약·독립 검증을 맡는다. 설계 작성 당시 화면은 비활성 안내였으며, 승인 후 실제 구현 상태는 연결한 기능 추적표를 따른다.

이 설계는 기존 [공통 제작 기획](../../product/character-workflow-live2d-plan.ko.md)과 [문서 계약 v0.1](../../handoffs/character-document-contract.md)을 좁힌 첫 구현 범위다. [누락 점검](../../product/plan-gap-audit-20261020.ko.md)에 다른 미완료 범위를 유지한다.

## 접근 선택

준비한 PNG 부위를 쓰는 제한된 자체 메시·파라미터 렌더러를 권장한다. 기존 문서 계약을 재사용하고 이미지 생성·Codex 연결과 독립적으로 움직임을 완성할 수 있다. 공식 Cubism 모델 재생 연동은 준비된 전용 모델과 별도 SDK 경로가 필요하므로 이번 첫 구현과 분리한다. 이미지 모델로 프레임을 매번 만드는 접근은 반복 비용과 형태 일관성 때문에 첫 구현에 쓰지 않는다.

## 첫 범위와 사용 흐름

1. `부위`에서 준비된 배경/몸·눈·입 등의 투명 PNG를 가져온다. 사용자 소재와 공개 가능한 자체 제작 예제 모두 같은 가져오기 경로를 사용한다. 한 변1024px 이내 캔버스·최대16부위부터 검증한다. 원본·소재 파일 바이트는 불변이다.
2. 이름·부모·앞뒤 순서·기준 배치를 정한다. 일반 이미지 한 장은 원본으로 유지하며, 움직일 부위와 가려진 배경이 준비되지 않으면 준비 상태를 안내한다. 자동 부위 분리·자동 리깅을 약속하지 않는다.
3. 부위에 작은 격자 메시를 만들고 조절점을 직접 편집한다. 파라미터를 선택해 최소/기본/최대의 기준 형태를 등록한다. 기본 형태의 displacement는 0이며 같은 정점 수·연결·UV를 유지한다. 열린 입 내부와 감은 눈에 필요한 그림은 소재 준비의 일부다.
4. `표정·동작`에서 눈 뜨기·입 벌림·호흡 슬라이더와 숫자 입력을 움직인다. 준비된 binding만 활성화한다. 현재 값 사이의 실제 중간 정점이 렌더링된다.
5. 눈 깜빡임·호흡의 2초 반복 곡선을 재생·정지하고 시간을 이동한다. 입은 수동 조절·시간 곡선 조절을 제공하며 음성 립싱크를 약속하지 않는다. 새 이미지 추론은 발생하지 않는다.
6. 현재 정지 PNG와 2초·24fps·48프레임을 출력하고 v2 프로젝트를 저장·재개한다. 미리보기와 출력은 같은 pose 계산을 쓴다.

큰 고개 회전·전신 포즈·물리·실시간 얼굴 추적·PSD·Cubism 전용 형식·동영상 인코딩은 기존 후속 범위를 유지한다. 색상 편집·Codex·외형3안 조합은 이 첫 수직 흐름 뒤에 이어지며 전체 계획에서 제거하지 않는다.

## 데이터·변형·재생

v2의 자산·부위·리그·3파라미터·프리셋·동작과 상한은 기존 계약을 기본으로 한다. `eyeOpen` 기본1, `mouthOpen/breath` 기본0, 모두0..1이다. 정점의 기준값에 파라미터별 선형 보간 displacement를 더하고 부모 affine을 적용한다. 여러 파라미터는 같은 base에 합산한다. 비유한 값, 범위 밖 값, 잘못된 참조·삼각형·UV를 거절하고 마지막 유효 상태를 남긴다. 모든 파라미터를 합성한 pose마다 각 삼각형의 signed area 방향을 base와 비교하고 절댓값이0.0001px² 미만이거나 뒤집히면 해당 조작을 거절한다. 재생/출력 중이면 중단하고 대상 부위와 사유를 표시한다. 완전히 납작한 삼각형을 감은 눈으로 쓰지 않고 유효 면적을 가진 감은 눈 형태를 준비한다.

`evaluatePose`와 별도 `drawPose` 경계를 사용한다. 렌더러는 DOM·네트워크·문서 변경 없이 삼각형별 UV→정점 매핑과 RGBA 합성을 수행한다. 먼저 기존 브라우저 Canvas 경로로 검증하며 새 라이브러리 설치는 첫 설계에 포함하지 않는다. 준비한 배경과 분리된 부위만 합성해 원래 눈·입이 겹쳐 보이지 않게 한다. 배경 미준비 상태에서 기존 원본 위에 새 눈을 덧그려 동작 성공으로 처리하지 않는다.

재생은 경과 시간으로 곡선을 평가하며 프레임 수에 따라 속도가 바뀌지 않게 한다. 화면 전환·문서 교체·정지 시 예약 프레임을 해제한다. 숨겨진 탭은 정지하고 명시 재개한다. 각 곡선은0초와2초 끝점을 포함하며 최대32키다. 재생/시간 이동의 평가값은 런타임 미리보기로 두어 매 프레임 문서 revision/undo를 만들지 않는다. 사용자가 정지/저장을 요청하면 현재 보이는 값을 한 명령으로 확정한다. 문서 교체 시에는 옛 문서의 미리보기를 폐기한다. 재생 중 플래그·재생 시각은 프로젝트에 저장하지 않는다.

첫 기본 곡선은 눈 `[(0,1),(.85,1),(.95,0),(1.05,1),(2,1)]`, 호흡 `[(0,0),(1,1),(2,0)]`이다. 입은 수동값 유지가 기본이며 선택 가능한 동작 예시 `[(0,0),(.5,1),(1,0),(1.5,1),(2,0)]`를 제공한다. 사용자가 키의 시간·값을 숫자로 수정할 수 있게 한다. 루프 끝점은 시작값과 같아야 하며 그렇지 않으면 반복 재생을 차단하고 보정 안내를 한다.

출력은 t=k/24, k=0..47의 동일 계산을 사용한다. 브라우저가48 PNG와 manifest를 하나의 ZIP으로 전달한다. 파일명은 `frame-0000.png`부터 `frame-0047.png`, manifest는 크기·fps·duration·샘플시각·사용 rigHash를 기록한다. 배경 자산이 있으면 합성하고 없으면 준비된 분리 소재만 투명 배경으로 출력한다. 불완전한 원본 위에 부위를 덧그리는 출력은 차단한다. PNG 바이트 합계128MiB 상한, 프레임별 진행·취소를 적용하고 전 프레임 검증 전 다운로드를 만들지 않는다. 취소·실패는 임시 Blob 참조를 해제하고 완료 파일을 내놓지 않는다. ZIP 패키징은 추가 외부 라이브러리 설치 없이 구현한다.

소재·마스크·원본·메시·기준 형태 변경 시 기존 rigHash와 연결된 프리셋/동작을 다시 검증한다. 다른 원본에 리그를 자동 이식하지 않는다. 준비되지 않은 부위는 사유를 표시하고 마지막 유효 정지 상태를 유지한다.

## 저장·호환·되돌리기

v1은 기존 파서로 먼저 검증해 원본·후보·브리프·선택 이력을 새 문서로 가져온다. 기존 파일을 덮어쓰지 않고, v2에 소재·부위·리그·키폼·현재값·시간 곡선·선택을 저장한다. 첫 저장/출력은 브라우저 파일 다운로드가 소유하며 신규 서버 프로젝트 저장 API는 필수 선행조건으로 만들지 않는다. 문서 로딩·디코딩 실패는 현재 작업을 보존하고 늦은 비동기 응답을 폐기한다. 상한을 넘으면 조용히 일부 소재를 버리지 않고 저장을 중단한다. 배경 준비 확인은 사용자가 실제 깨끗한 배경을 가져와 미리보기 후 확인하는 수동 단계이며, boolean만으로 픽셀 복원 완료를 자동 판정하지 않는다.

첫 구현의 undo/redo는 한 번의 조절점 드래그·배치·슬라이더 조절을 한 단위로 묶는다. 문서 모듈의 명령은 부위 추가/제거·계층/순서·변환·소재 교체·메시/키폼 변경·파라미터 설정·프리셋/곡선 저장으로 제한한다. 소재/메시 교체와 종속 리그 무효화는 한 commit/undo로 묶고, 검증 전에는 원본 문서를 바꾸지 않는다. 명령의 type/args allowlist와 inverse patch는 문서 모듈 구현 계획에 함께 고정한다. **승인 범위:** 현재 편집 결과와 선택 기록은 저장하고 undo 스택은 런타임 한정으로 둔다. 다시 열었을 때 과거 undo를 이어 쓰지 못함을 명시한다. 이전 기획의 이력 복원 문구는 이 최신 승인 범위로 정정하며 미래의 이력 영속화를 현재 기능으로 약속하지 않는다.

## 완료 판정

- 실제 캐릭터의 눈·입·호흡 각각을 최소·중간·최대로 조절한 화면과 정점 기록이 있다. 기존 PNG 전환·페이지 애니메이션으로 대체하지 않는다.
- 자체 제작 예제뿐 아니라 사용자가 준비한 PNG 부위도 같은 UI로 등록·메시/기준 형태 편집·저장·재개할 수 있다.
- 깜빡임·호흡 재생/정지·시간 이동이 작동하고, 이미지 요청은0회다. 숨김/프로젝트 교체 후 재생이 남지 않는다.
- v2 왕복 후 같은 소재·리그·파라미터·선택·곡선을 복원하고 같은 정지 렌더를 얻는다. v1과 잘못된/과대한 파일도 검증한다.
- 48개 프레임의 크기·알파·순서·실제 픽셀 변화를 확인하고, 중단/실패 시 완료 파일로 오인시키지 않는다.
- 준비 소재·수동 작업·미지원 항목을 드러내고, 실제 장비에서30fps·입력100ms 목표를 측정한다. 미달이면 실측값과 제한을 보고한다.

자체 검토: 기존 v1과 v2 구분, 알파·배경 준비, 자동 리깅 미약속, 새 추론0회, 모듈 소유권, 48프레임 시점, 실패/무효화 및 undo 범위 차이를 확인했다. 현재 설계·계획 승인 후 기존 담당이 실제 코드를 구현 중이며, 앱 동작 전체 완료는 독립 검증 뒤 판정한다. D:/Pankeki는 Git 저장소가 아니므로 설계 파일을 로컬에 보존하며 임의 저장소 생성·원격 커밋은 하지 않는다.
