# Pankeki 최소 실행·검증 계획

> 실행 담당: 명세가 요구한 독립 하위 작업을 병렬 수행하고 root가 통합·실제 GPU 실험·최종 검토를 담당한다. 사용자가 구현까지 명시적으로 요청했으므로 문서 승인 대기로 중단하지 않는다.

**Goal:** 로컬 ComfyUI 생성, 정확한 완료 캐시, revision 표시 제어, 실제 ROI crop과 원본 보존을 실행하고 재현 자료를 남긴다.

**Architecture:** Python 표준 HTTP 서버와 vanilla browser UI가 immutable 요청을 받아 단일 worker에서 ComfyUI HTTP/WebSocket으로 실행한다. cache/planning/composite/adapter/jobs/metrics를 분리한다. 입력·출력·recipe는 job별 디렉터리에 보존한다.

**Tech Stack:** Python 3.12, Pillow, NumPy, websocket-client, unittest; 별도 ComfyUI/PyTorch CUDA 환경.

**Spec:** `D:\Pankeki\CODEX-TASK.ko.md`, `START-HERE.ko.md`, `RESEARCH.ko.md`.

## 공통 제약

- 기존 사용자 작업·프로세스를 보존하고 D:\character-foundry는 수정하지 않는다.
- 로컬 무료 도구만 사용하며 외부 게시·계정·유료 서비스는 사용하지 않는다.
- 캐시 off와 baseline 경로를 유지하고 근사 캐시·모델 타일 추론은 기본 비활성이다.
- 실제 GPU, 모의 프로토콜, CPU 이미지 연산, 계획 시뮬레이션의 결과를 구분한다.
- 측정하지 않은 시간·GPU 메모리는 null로 기록한다.

## 검토 초점

1. 제출 timeout 후 중복 GPU 작업: 자동 재제출 금지, 불확실 상태 노출.
2. 새 revision과 늦은 preview/final: 현재 revision만 표시, 취소는 전역 interrupt 없이 결과 무시.
3. 모델·입력·외부 상태 변경: 내용 hash로 의존성을 확인하거나 캐시 bypass.
4. 경계·한 픽셀·빈 mask: 정렬 crop/padding과 정확한 외부 픽셀 보존 검사.
5. 서버 끊김·오류·손상 캐시: history 재조회, 명확한 오류, 실패 결과 저장 금지.
